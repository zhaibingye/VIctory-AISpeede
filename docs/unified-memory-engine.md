# VIctory Unified Memory Engine：替换任务书

**只替换内存后端。** 保留 CPU 执行、Shader 翻译、异步 Pipeline、Xbox
HLE 和 Loader。切换后删除 Shadow Buffer、旧回读路径和
VICTORY_IN_PLACE，不允许错误时隐藏回退。Git 保留旧版历史；本分支在切换
和验收之前不是统一内存引擎发行版。

## 容量与物理后备

- **10 GiB RAM** 是模拟主机总容量，内核与标题共享；维持原有 7,776 MiB
  零售标题报告值。保留地址不等于提交物理页。维持 Xbox 指针范围、保护、
  映射和别名语义，不强迫标题的现有地址处于单个连续宿主区间。
- CPU 地址、GPU 页表和资源视图统一指向物理页编号；首版以 64 KiB 为
  一致性粒度。别名只记账一次。释放再分配不能让旧句柄命中新页。
- **5 GiB 独显驻留**是硬配置上限。有效准入上限同时受 DXGI 当前预算、
  驱动和交换链保留开销约束。纹理、深度副本、稀疏堆、临时上传、回读均
  要入账，且以实际 backing 的生命周期扣费；非本地 GPU 内存占用 RAM。
- 15 GiB 不是游戏可用容量。显存和 RAM 不是物理统一，跨 PCIe 的成本仍
  在。驱动突然下调预算时冻结准入并淘汰可回收页；已提交页等 fence 后才能
  释放，必须记录暂时超出的字节数，不能假装已经降下来了。
  参考 [D3D12 Residency](https://learn.microsoft.com/en-us/windows/win32/direct3d12/residency)。

## 所有权、驻留与提交

| 事件 | 不变量 |
| --- | --- |
| CPU 读 | RAM 版有效则直接读；否则等待 GPU 写 fence，并仅回读所需页。 |
| CPU 写 | 部分写先确保当前 RAM 版本有效；已知全页覆写可不回读，但不能越过在途 GPU 访问。 |
| GPU 读/部分写 | 仅在缺页或 GPU 版本过期时上传，并在完成后使用。 |
| GPU 全页覆写 | 仅在已证明写全页且前序依赖满足时跳过上传。 |
| 淘汰 | 录制占用或 fence 未完成的一律不能动；干净缓存可丢弃，GPU 权威页先回读。解除映射并结束最后一个引用后才归还预算。 |

Probation 和 Protected 是两级热度；Pinned 是独立约束。首次驻留进入
Probation，重复命中晋升。Protected 超额则降级最旧项，首先从最低优先级的
Probation 驱逐。不可分割的一次提交若本身超预算，明确报错或走新引擎
定义的非本地放置；可以拆分的工作集按页分批。首版只有一条单调的 D3D12
direct 队列；支持多队列之前，fence 必须带队列身份，不能比较裸数值。
纹理的 GPU 原生布局是派生资源；GPU 写入派生布局时同样要登记子资源和
回写格式，不能把 CPU 源数据视为仍然有效。

## 替换顺序和门槛

1. **策略核心**：guest 管别名/物理 ID，budget 管 RAM 和 DXGI，
   coherence 管权威位置和 fence，residency 管 2Q/优先级/pin。
   先做不依赖游戏和驱动的合成测试。
2. **物理后备**：把 HLE 的提交、释放、别名接入同一账本；审计
   resource、sparse、twin、texture、host 的创建和映射入口，移除私建路径。
3. **页表和 GPU 迁移**：重做 memory.rs 的稳定映射；接通逐页上传、下载、
   fence 等待和命令列表引用保留。D3D12 合成夹具严格比较
   CPU 写 → GPU 读 → GPU 写 → CPU 读的字节结果。
4. **原子切换**：接通 draw、bindless、descriptor、indirect 与纹理，
   同次删除 shadow.rs 及旧入口。此之前的可编译中间提交不等于双后端设计。
5. **验收**：用大于 5 GiB 的虚拟工作集验证分批淘汰；模拟 DXGI 动态
   缩减、分配失败、过期描述符及反复覆盖、映射/解绑。核对未变化页无
   搬运、GPU 写入不被覆盖、pin 结束前不回收。30 分钟另验 RAM/VRAM
   高水位无无限增长，记录命中率、传输量、峰值及等待时间。
   静态检查、CPU 策略测试和 D3D12 夹具分别报告，不冒充实机 30 分钟；
   不在用户电脑上自动运行游戏。

### D3D12 迁移夹具

`victory_memory::d3d12::Pages` 把同一套页状态机接到真实 D3D12 buffer 复制和 fence 上。
一份上传和一份回读暂存由所有页复用并记入 RAM 预算；本地页先预扣额度，
D3D12 分配失败则释放额度。GPU 产生的版本只有在复制完成、CPU 成功读回后才标记为一致。
Windows 可用 `cargo test -p victory-memory --locked` 运行 WARP 软件设备夹具，不需要游戏数据。
夹具校验整页内容、无变化时不重复上传、低预算拒绝、脏页淘汰及再驻留。

此夹具独占并同步等待 copy queue，只用于验证迁移语义。不把独立 committed buffer
当作生产页池，也不把逐次等待带进渲染热路径。下一步将传输接到统一的分块物理后备池、
主渲染队列与 HLE 映射生命周期，再切换游戏的内存入口。

### XMem 的实际后备接入

`XMemAllocatePhysicalPages` 现在先向 `victory-memory` 的 RAM 池申请整段 section
容量，再创建 Windows 后备，因为一个剩余视图可能让整个 section 继续存活。标题页号、
映射和 DirectStorage 的工作视图共用同一份后备；只有最后一个引用释放时才返还容量。
别名以稳定物理页号识别，不再用宿主指针当身份；OS 确认映射或解除映射后才更新索引。

这是 XMem 物理池的 **10 GiB 容量上限**，不是整个进程工作集：普通虚拟分配、渲染对象、
驱动以及旧 Shadow Buffer 未纳入本次切换。还需把生产渲染的 GPU 驻留连接到这些页，
才能统一核算和移除旧副本。

### GPU 提交持有物理后备

渲染队列将三条缓冲区读取路径（普通视图、绑定堆、裸地址页表）以及声明的 GPU 写入区间
归并后交给 XMem，按物理 section 保留后备。同一 section 的多个别名只保留一份引用；
每次提交的所有 chunk 完成 fence 并处理写回后才释放，未额外插入等待。

保活的是物理后备，不是游戏虚拟地址。旧 Shadow Buffer 仍负责当前的数据传输与写回；
这一步既没有切换写回目标，也没有改变 GPU 显存预算。后续应将统一页池和 GPU 写回
直接绑定物理身份，而不是临时虚拟地址。

### XMem 与真实 GPU 分配共用预算

XMem section、显存不足时放到非本地内存的 GPU 资源、UMA 的默认堆、
常规上传和 CPU 可映射的共享缓冲，都从同一个 10 GiB RAM 账本扣除。
提交的专用显存资源使用同一账本的独立 5 GiB 本地额度，按 DXGI 采样及保留空间下调；
DXGI 已包含的受管资源不会重复计算。缓冲按 D3D12 报告的分配大小预留，
稀疏堆按实际分配的 64 KiB 块预留。创建失败会释放预留；成功后由 D3D12
对象的 COM 引用持有，最后的引用消失才归还。

这是受管分配的上限，不是整个进程或显卡的实测占用。交换链、驱动、外部库、
普通进程内存等并未全部纳入账本。暂无按物理页换入换出的生产缓存，
旧 Shadow 的共享缓冲已计费，但数据路径未切换。

### 写回拒绝过期的物理绑定

提交在刷新前保存首见的 XMem 物理页身份。经视图写入、裸地址位图和按字节写回，
都在 CPU 比较和写入期间持有同一映射锁。如果地址已解绑或改绑另一页，就跳过旧写回，
不会覆盖新页。提交内后续批次的同地址快照不会覆盖首见绑定。
这一步暂不把被跳过的结果写回原物理页；直接打开 CPU 内存的旧实验路径也不经过这次写回检查。

### 有提交前快照的写回可直达原物理页

按字节比较的 GPU 写回已有提交前快照，所以地址被重绑时不用丢弃结果：
从提交保活的 section 打开一个短生命周期的单页视图，把 GPU 改动与原页的当前
内容合并。即使原页的标题句柄和所有别名都释放了，也不会误写新页。临时视图写入
会通知原页当前的别名，但不会把新虚拟映射标为同步。没有稳定前镜像的位图路径仍然
拒绝过期目标，避免把整页的旧内容误作 GPU 改动。

### D3D12 页传输夹具自动按预算换出

夹具申请本地页遇到预算压力时，按 2Q 选择已完成 fence 的冷页；当前复制的两端
不会被选中。脏页先回写再释放，干净页不回读。预算缩小也会回收实际 D3D12 缓冲。
WARP 回归覆盖两页预算流转三页、脏页回收，以及预算降到零后重新准入。这个传输夹具
仍不承载游戏渲染；发布前需要接入真实统一页池并替换旧 Shadow 数据路径。

### 物理页缓存的 D3D12 分块堆

页传输后端改用最多 1 MiB 的 D3D12 本地堆，每个 64 KiB 页对应一个固定位置的
缓冲区；淘汰后复用同一缓冲区，不重新创建与旧资源重叠的缓冲。预算按整块堆计入，
包含暂未占用的槽。预算收缩时即使有效页数已低于上限，也会回收超额的实际堆；
完成 fence 与必要的脏页回写后，最后一个有效槽才让整块堆释放。
目前仍由 WARP 夹具验证，不是游戏实际渲染路径。

### 生产渲染的读取与写回使用同一物理快照

现有渲染批次在刷新常规缓冲、绑定堆与裸地址页表时，从提交捕获的物理后备读取。
地址仍映射原页时直接读；改绑后按连续页打开短生命周期 section 视图，不从新页
读取旧提交。发生改绑的旧副本保持脏状态，让下一次提交重新读新的映射。Windows
回归同时校验重绑后的读取和按字节写回。现阶段生产页数据还经过旧缓冲，
这一步没有让物理 D3D12 分块堆成为实际渲染后端。

### 物理分块之前的 shader 跨页读取

裸地址的标量读取、global 读取和 global 写入保留单页快速路径，但跨 64 KiB 时重新
查询目标 dword，避免把第二页当成第一块缓冲的尾部。Windows shader 回归使用两个
互相独立的 D3D12 descriptor 验证边界以及写入标记。普通硬件视图与渲染页池仍需
迁移，不能据此发布为新后端。

### 渲染与夹具共用页表编码

生产裸地址页表与着色器回归现在共用二级页表编码。页条目记录描述符对和
32 位环绕偏移，两个虚拟别名可以指向同一个缓冲区和同一个非零页偏移。
回归覆盖高地址别名及落在不同资源的跨页读写。生产路径仍然从旧缓冲生成
条目，尚未使用驻留页池。下一步要用提交捕获的物理身份分配槽、构建别名
条目并在 fence 后按物理页去重写回；之前不切换或发布。

### 渲染器 D3D12 页槽与 direct queue fence

渲染器侧的页槽以捕获的 XMem 物理页号为键。16 个槽共用一个 D3D12 缓冲，
描述符可以按整块绑定，页表按槽偏移寻址。独显 slab 只从受管显存预算扣费，
拒绝把显存压力隐式转嫁给 RAM；UMA 使用受管 RAM。录制 pin、提交 fence 和
已完成但未回写的脏页都限制槽回收。WARP 测试用渲染器主 direct queue 往返
两个页槽，并验证原物理映射、别名和回收条件，没有新增逐页等待。

这些是原子切换会用到的组件，尚未启用到游戏的 draw/dispatch。后续要让提交
阶段从已捕获的映射分批取页，整块生成描述符、迁移命令和页表；派生资源与
写回也要使用同一后备，不能为了提前启用页池而保留两份 GPU 权威数据。

提交准备现在按捕获的物理页去重 pin，并为每个 slab 只分配一对描述符；页表
的多个 VA 叶子仍各有标记位，能关联回同一物理页。主 direct queue 夹具
批量上传后以真正的 D3D12 绑定读取两个别名，再批量回读。每个 slab 每批只
进出复制状态一次。尚需把这一批次接到标题提交，并统一原生视图和着色器写入
的状态管理，尤其不能在同一资源同一 shader 调度中混用 SRV 与 UAV 状态。

裸地址访问的页池编译模式下，读写都使用原始 UAV 描述符，保持 slab 在同一个
D3D12 状态；只有写入设置写位，未绑定读取仍报告 miss。Windows 回归专门把
同一资源的 SRV 描述符置空，验证新模式未暗读 SRV。主 direct queue 回归还对
同一物理页的两个别名依次做读取、写入、UAV barrier 和回读。这一 ABI 将随
生产页池一起启用，主渲染现有构建仍用原来的描述符路径。

提交的物理快照使用一份已记账的 CPU 可见暂存：先从捕获的物理页读取，再用
相同字节上传并作为 fence 后回读的前镜像。合并只修改 GPU 实际改动的字节，
保留 CPU 独立写入；严格检查原物理身份与完整写入结果。部分写入或重映射
失败不能将脏页标为干净。暂存的这一阶段先以完整工作集保持正确性，切换前
还需要接入写监视或版本验证以只上传变化的页，并分批控制暂存峰值。

新页提交已复用渲染器真实 direct queue、fence 和提交锁。接口先完成物理页、
描述符和快照的准入，再批量提交上传与 shader；UAV 位图指明实际需要回读的
物理页，非空时只再提交一次回读批次。页表、描述符、生存引用和上传镜像
一直持有到相应 fence/合并完成。命中未绑定页、设备移除或写回失败会停止
该运行，不把结果交给游戏。入口由 WARP 集成测试调用；游戏完整的直接视图、
绑定堆、间接命令与纹理尚未接管。

页队列只为物理页的 CPU 快照与上次确认驻留的 GPU 内容不同时记录上传。读回后
记下 GPU 字节的摘要，而不是混合 CPU 并发写入后的摘要；否则下一次会错误跳过
CPU 新内容。仍需生成已记账的 CPU 前镜像以支持按字节合并，而不是宣称热路径
已经不扫描 RAM。

普通虚拟内存的受控 commit/decommit/release 现在进入同一捕获表。只有完整
提交的 64 KiB 私有页获得内部物理身份，每次解除提交再复用得到新身份，
即使虚拟地址未变。标题的 VirtualAlloc/VirtualFree 和 XMemVirtualAlloc
经 Windows 确认成功后才变更记录；私有页被释放后没有可重新打开的 XMem
section，旧提交只会拒绝该读写，不会写到新分配。这一步没有给普通 RAM
分配完整记账，也没有把未经过已覆盖接口的堆/映像/映射页当作可信物理页。

普通私有 RAM 的硬预算已具备启用接口：Windows 提交前按新增的 4 KiB 单元
预扣同一 10 GiB 账本，失败还原预扣，成功后按实际提交修正；重复提交不
双算，成功 decommit/release 返还，启用也覆盖先前已跟踪的提交。接口先保留
未启用，避免在旧 Shadow 并存时把同一组游戏数据的额外旧副本计成新引擎
正常开销。测试在独立预算中使用真实 Windows 提交和释放。

真实标题的缓冲复制已在命令记录里保存为 guest 范围，不再用无类型的三元组。
新绑定分割源和目的各自的 64 KiB 边界，并用同一次捕获取物理号；两个 VA
可能指向同一个物理页，两个不同物理页也可能占同一 native slab，所以 GPU
路径需要先 gather 再 scatter。游戏版现阶段仍按旧提交语义执行这条命令；
新绑定不会漏页后只复制部分数据。

页队列已有实际 D3D12 缓冲复制入口。在同一批次中先读取全部源片段到受
预算约束的暂存，再写入目的片段，避免物理别名或同一 slab 的读写状态冲突。
明确标记的目的物理页和 shader 脏页经过同一批量回读与写回。WARP 覆盖同一
物理页的两个虚拟别名发生重叠复制；真实标题命令流仍未切至此入口。

顺序缓冲复制可共享一次物理页捕获、同一个最大单次复制大小的暂存、一次脏页
合并。每条复制完整 gather 再 scatter，后一条能看见前一条的更新；任一范围
未捕获会拒绝整批，而不是前半批已提交后才报错。该入口仅接收闭合的复制序列，
不能跨未迁移的着色器、间接命令或纹理操作重排。

接入命令录制边界：标题缓冲复制通过原来的操作记录入口保留顺序，新的批量编码
只接收已关闭且能证明仅含复制的整段提交。原生录制、未关闭列表、纹理状态和
延迟回调都会拒绝整段，不能先执行某个列表再报错。Windows 回归记录两个标题
命令列表，验证前后依赖和混合列表拒绝；实际游戏队列尚未切换，需先为绘制、
纹理和间接等命令补齐同一录制与下发协议。

固定功能的顶点和索引输入可从已捕获的 GPU 物理页生成连续的原生视图。
在命令流使用点汇集，能读到前一条 GPU 写入而不用先回 CPU；短期视图仍由显存
预算记账，不作为权威副本。Windows 回归覆盖跨页和别名，绑定顶点、索引两种
原生视图并回读底层字节。真实绘制仍未切换，后续需在真实有序命令流中接入，
并控制同一批反复使用输入视图时的额外复制。

复制、顶点和索引绑定现在可以在同一个有序提交里预先校验并依次编码。
实际标题绘制记录保留绑定的 guest 地址；仍未经改写的 native 绘制等会拒绝
整段。验证坏输入不能让前面的复制提前执行。没有对游戏切换后端。

有序队列可以下发一个完整的原生绘制操作：保留 PSO、根签名、单色目标及
输入，在同一原生列表中读取之前复制到物理页的顶点。WARP 验证从红色底色
变成指定绿色像素，而不是只比较缓冲。这一形式仅用于由调用者证明没有额外
着色器资源依赖的绘制，游戏的着色器资源闭包、纹理状态和间接命令还未迁移。

已翻译的标题 PSO 可用元数据判定何时只需要普通根常量。这类绘制捕获所需的
常量快照；缺值、重复目标字或未知布局拒绝准入。任意地址、描述符堆、表和
根视图仍拒绝，不会当成空资源继续绘制。像素回归由根常量决定颜色，并继续
验证同批 GPU 复制后的输入。真实游戏队列仍未切换。

标题状态可冻结为闭合绘制：保留目标资源和 RTV 描述，捕获单个视口、裁切框、
混合因子和实际设置过的常量字。深度、未知 native 状态或不匹配的格式会拒绝。
目标必须已由主机维护，绘制在直接队列锁下临时切至 render-target 并还原，不在
校验时提前发布状态；WARP 回读从原有 COPY_SOURCE 状态开始和结束。实际游戏
仍走旧提交，纹理上传、采样和间接依赖需继续迁移。

闭合绘制可从当前 GPU 页读取间接参数和可选计数。复制到有预算的原生暂存后
使用原有 GPU 限幅器，整批共享工作预算，不回读 CPU，也不修改标题原参数。
Windows 像素测试先在 GPU 生成顶点、参数和计数，再从同一列表执行间接绘制。
目前只覆盖闭合绘制/索引绘制签名，实际标题混合命令流和间接派发尚未切换。

已能从明确给出行跨度的线性 RGBA/BGRA 页生成原生只读纹理。按行汇集图像
字节但不读取源 padding，目标行布局由 D3D12 查询；同一 slab 每次只切一次状态。
WARP 回归覆盖别名跨 64 KiB、GPU 前序复制、源和目标行跨度不同。原生纹理和
暂存占用统一预算；正式采样绑定，以及 tiled、BC、mip 和写入纹理还未迁移。

闭合原生绘制可绑定单个显式只读纹理 SRV，保留资源和描述符直到 fence。
像素回归用静态点采样器读取同批 GPU 刚从蓝更新为绿的纹理，再校验绿色像素。
这不是标题动态描述符堆的迁移；实际着色器 PSO 仍须提供可验证的完整绑定。

纹理 SRV 与裸地址页描述符共用提交的 HostHeap，按 fence 回收动态槽，不再
每次绘制新建描述符堆。标题资源与默认 SRV 已能提供严格核验的线性布局，
行跨度取自标题布局库；写入型、默认 tiled、重解释和多 mip 资源会拒绝。
面向真实着色器的描述符表和 bindless 地址，还未接到该准入结果。

译器可追踪实际的 2D texture operand，证明它引用了标题描述符表中的哪些静态
槽。只靠 used-resource 条目不能界定实际索引；遇到动态地址、wave 选择、非静态
采样器、可写纹理或其他资源类型，证明不成立。宿主可据证明清点默认线性 SRV，
但还需在提交时建立连续的原生槽区和重写根常量里的表基址。此步未切换游戏。

静态纹理表现在可从标题已绑定的描述符读取有效代次，捕获默认线性 SRV，提交时
在统一堆分配连续槽区。只初始化证明所需的纹理，空洞写类型明确的 null；翻译
后的根常量表基址改写为新槽区的字节偏移。证明按原着色器对象缓存。未知表、
动态索引、非线性或不兼容资源仍拒绝，实际标题的提交入口尚未切换。

加固定槽偏移，采样 GPU 刚更新的纹理。直接索引绘制在根签名前绑定堆。测试
用 Windows SDK 自带的 DXC 构建像素着色器，不访问游戏文件。

开发构建可用 `--features paged-title` 把 Xbox 命令队列的真实提交入口切到
新后端。在这次构建中已支持的绘制和间接绘制只记录新操作，提交失败立即报告，
不会偷偷走旧路径。此功能尚不对默认构建开启：清屏、纹理和动态资源等未迁移
命令仍可能拒绝整批，目前不能把开发入口当成可玩版本。推送默认只做 Windows
编译检查；原有 WARP 工作流保留供显式手动运行。

严格入口接入真实标题的颜色清屏。全清可初始化目标，同一批次后续绘制或
局部清屏可继承；未初始化的局部清屏、错误 RTV 和未知命令仍拒绝整批。目标
权威状态在原生 fence 完成后才发布，失败不会让下次误认资源已初始化。深度
清屏、多附件和纹理混合等仍需迁移，不代表游戏已能使用新构建。

严格开发入口也接入深度/模板清屏和单深度附件绘制，捕获 DSV、模板参考值，
使用与 PSO 匹配的格式。全清所有平面才可初始化；部分清屏要求已初始化，
目标状态在 fence 完成后发布。只接纳已证明的单样本、单子资源和可写 DSV。

严格提交把直接地址复制和资源屏障纳入同一有序操作流。支持全资源原生转换
以及页数据的全局 UAV 顺序；分割、混叠和未支持的状态不执行。绘制和清屏从
同一提交计划读取状态，计划只在 fence 之后归还状态和初始化权威。

严格标题入口将直接 dispatch 和工作量受限的间接 dispatch 记入同一物理页队列。
绘制和计算共享着色器常量、静态纹理表和描述符准入，不再各自维护绑定逻辑。
目前仍只接纳已证明的读依赖；任意地址、UAV 输出和未界定索引不能执行。

绘制和计算的根常量缓冲区（CBV）现在从统一页生成：按译器声明的 64 KiB 窗口
捕获，要求 256 字节对齐、整个窗口有可靠后备，且按提交顺序读取最新 GPU 字节。
同一调用里的相同 CBV 共用一份预算内的原生缓冲。未绑定、未捕获及其它根视图
仍会拒绝，不回到 Shadow Buffer。
