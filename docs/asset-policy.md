# 资料存放规则（第一条）

**仓库不保存任何游戏资料。** 所有转换产物都在用户电脑上从用户提供的文件生成。这同样适用于用来测试的其他游戏和任何其他专有资料。

## 禁止提交

无论是文件、字符串字面量、测试样本、快照还是文档，都不得包含：

- 模型、纹理、着色器、音频、视频、文本、归档等游戏资源。
- 游戏可执行文件或它的任何部分，包括数据段、字符串、表格、资源，以及下文允许的定位特征之外的代码。
- 上述资料的衍生内容，包括转换后的资源、反编译或反汇编代码、着色器转储、提取的表格和截图。

## 允许提交

- 项目自行编写的格式解析代码。
- 构建标识：可执行文件的 BLAKE3 哈希及 CodeView GUID 和 age 字段。
- 按构建版本记录的函数钩子偏移，名称由本项目自行命名。
- 用于定位可执行文件中函数或数据的字节特征。
- 项目编写的少量互操作常量，如魔数、枚举值。
- 由项目自己的代码生成的测试数据。

## 唯一例外

`crates/victory-formats/src/bcpack-tables.bin`（约 78 KB）包含 BCPack 格式的常量表，包括熵模型、索引秩表、控制码及各格式的字典。解码 BCPack 数据必须使用这些确切的表，无法推导生成。项目所有者于 2026 年 11 月 23 日决定随 VIctory 提供，并在 `xtask/src/policy.rs` 登记为例外。这些表属于该格式，并非本项目作品，不受仓库许可证覆盖。除此之外，不接受同类资料。

## 路径配置

游戏、测试游戏、缓存和存档必须位于仓库外。可在 `victory.toml` 配置路径。
未指定缓存或存档路径时，默认在 `victory.exe` 所在目录创建 `cache` 和 `data`。
若程序位于源码仓库内，请显式设置仓库外的路径。

## 检查机制

1. `.gitignore` 排除常见的数据文件，避免它们被误加入 Git。
2. 提交前钩子运行 `cargo xtask policy`，用 `cargo xtask install-hooks` 安装。该检查只准许清单内的文件类型，要求文件小于 512 KiB，不包含二进制数据、已知二进制特征或大段连续的十六进制/Base64 文本。例外应在 `xtask/src/policy.rs` 记录原因。
3. 运行时，写入衍生数据的路径必须通过 `victory_core::ensure_outside_repo` 检查。
4. 需要真实文件的测试从环境变量读取路径；未设置则跳过。此类测试只验证属性，不把真实数据保存为快照。

## 误提交的处理

仅在下一次提交中删除文件，不会从 Git 历史清除它。维护者需协调历史重写（`git filter-repo --path <file> --invert-paths`）和强制推送，再让协作者重新克隆。
