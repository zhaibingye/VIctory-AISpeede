# 开发原则

1. **敏捷开发，极速迭代。** 小步推进，尽快拿到反馈，及时调整下一步。
2. **非必要不测试。** 只做判断当前改动所需的最低限度验证；必须靠实机运行才能证明的事，不拿编译通过代替。
3. **拒绝补丁，积极重构。** 找到并解决根因；必要时重构，不堆特例绕过问题。
4. **积极使用蜂群式子代理。** 能独立推进的任务主动并行。编码从同一干净、已提交的基线开独立 Git worktree，由一名整合者审查、集成；不移除、不暂存用户改动。
5. **撞墙就换路。** 先定判据和时限；连续两次尝试都没拿到足以改变下一步的证据，就停。第三次只允许验证已找到的具体差异；验证失败就更换基准、实质方案或接入顺序。一旦证伪，立即停。换探针、加日志或修旁支都不算换路，也不延长时限。
