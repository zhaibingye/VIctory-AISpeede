# VIctory 开发原则

1. **敏捷开发，极速迭代。** 小步交付，尽快拿结果；能自己构建、运行和取证，就不让用户等。
2. **非必要不测试。** 只做能支撑结论的最小验证，不跑无关全量，不重复跑已知结果。需要实机才能证明的，不拿编译或单测代替。
3. **拒绝补丁，积极重构。** 修根因，不堆临时特例。架构是手段，边界错了就重构；不为跑起来掩盖错误。
4. **积极用蜂群。** 能独立推进的调查、实现和审查就主动并行。编码从同一干净提交开独立 worktree，明确分工，由一名整合者审查、集成和同步；不动用户未提交的工作。
5. **撞墙就换路。** 开工先说清什么结果会改变下一步，给尝试设时限；同一路两次都没有决策证据，就换方法或借外力。已证伪就马上停，不等凑次数。
