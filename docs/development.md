# VIctory 开发原则

**以正确、可复现的实机结果为目标。架构是手段，不是承诺。** 能用宿主能力保持游戏可观察行为，就不用复刻来宾过程。可以借鉴独立实现、删掉错误抽象或重选架构；不以跳过真实工作、伪造同步、掩盖画面错误或退回 Shadow Buffer 冒充 VNME 的成功。[VNME 架构与验收](vnme.md)定义不可放宽的边界。

## 证据止损

1. **先写判据。** 用一句话说清要区分的解释，以及观察到 A 或 B 时各改什么。两种结果都不改变下一步，就不做。只改最能判别的变量；能用现有证据回答，不再重跑。
2. **到点换路。** 一次尝试最多 45 分钟；超时未得证据算一次。连续两次没有足以改变下一步的可复核证据，就停止同一路线，找独立实现、参考资料、独立审查，或缩小到可对照的边界。路线被证伪立即换，不等时间用完。构建、日志、提交、轮数或改个说法都不续时。
3. **第三次只验已找到的差异。** 已有明确差异才做最小改动和回归，不留第三次继续猜。记录实际证据、因此作出的决定；换的是假设、对照或实现边界，不是给旧方法重开计时。当前尝试的起止时间与记录留在本地，而不是追加到原则页。

实机越过已知卡点，或找出一处可复核、能设计改前失败与改后成功对照的行为差异，才是当前卡点的明显进展；单纯多一份“未观测到”的报告不算。证据不足可以停，不把猜测写成结论。

## 对照、实现与验证

- **先区分目标和方法。** 按实际来宾对象、访问范围与相对顺序配对行为，不按编号、地址或尺寸认同一资源。参考实现优先用锁定的公开源码，独立构建与运行，尽量对齐同机器、同游戏入口、同配置和输入；明确仍不同的变量。取的是行为证据，不整库合并，也不把参考端没报错当成它画对了。
- **验证成本与风险匹配。** 文档改动检查链接和陈述来源；语义用能区分正反例的定向测试；兼容性和可玩性看实际构建、实际启动路径、画面与输入。按需继续做峰值、帧时间和稳定性验证；不为形式跑全量或重复已知坏包。离线测试、编译和实机各自回答不同问题。能自行构建、运行和采证就自行完成，只有必须由用户提供输入时才问。
- **一个整合者，独立任务并行。** 有可独立推进的调查、实现或审查就主动拆分；编码蜂群从同一干净、已提交的基线分配独立 Git worktree 和文件责任。整合者审查实际差异、核验、提交和正常快进同步；不暂存或改写用户工作来凑基线，不强推。交接注明基线、改动标识、验证命令与结果、是否实机、同步状态。
- **构建与资料隔离。** 工具链、下载项、缓存和中间产物集中在被忽略的 `依赖/`；可交付程序按源码提交分目录，不覆盖旧包。运行缓存、存档、原始日志和画面留在仓库外，不修改原始游戏文件，不分发游戏内容。锁定构建配置并核对可执行文件哈希；只提交源码、测试与脱敏证据，遵循[资料规则](asset-policy.md)。面向用户的说明、配置注释和日志默认中文，保留命令、配置键和错误标识。

记忆不是规范，也不是轮次流水账。只沉淀核实过且能复用的事实和反例；证据变化时更新原位置，合并重复条目，不在各页复制同一套结论。以当前源码、测试、实机记录和用户要求核验，不让历史记忆覆盖新证据。不记录凭据、原始游戏地址或本机私有路径。
