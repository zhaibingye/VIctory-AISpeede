# VNME 实机与验证证据

这里记录当前实机基线和足以影响路线的对照，不按轮次追加。正确性与发布门槛见[VNME 架构](vnme.md)，实验与止损规则见[开发原则](development.md)，可复用的实现知识见[项目记忆](../MEMORY.md)。本页整理自 `4cce33f346c0a9b1d96913a1b35f0c8eab53a1fc` 及其 Git 历史，没有新增实跑。源码基线、实际运行的构建和记录提交是三件事。

## 当前实机基线

| 对象 | 实际运行的源码 | 到达阶段与记录 |
| --- | --- | --- |
| VNME | `8c7269a0c471043594af1ce34f31bfe3a58b02b2`，带精确绑定 PS 的一次性诊断构建 | Windows Series S 配置，按 A 后在 `draw 15` 编码时首次报 `MissingTextureContent`。结果及探针撤出见 `d8b709c`；后续夹具不是新实机包。 |
| 独立参考 `fxceless/victory-fork` | `2eade68cade9b2f8cd2511cc97328e83f58508c3`，干净源码锁定依赖离线构建，Rust 1.98.1、Windows x64 MSVC、dev、`diagnostics,blake3/pure` | 按 A 后，送显读回确认从继续提示进入开场过场，随后到可辨识的语言选择；由采集者在限定时间后停止。记录见 `4cce33f`。 |

- **可比条件。** 同一 Windows 机器、同一游戏入口（输入文件 BLAKE3 一致）与 Series S 配置，均直接 `run --execute --console series-s`。fork 用新存档、缓存和日志，未用 DLSS、帧生成、额外光追或 1440p 补丁；提示可见后用内置 `VICTORY_KEYS_FILE` 发一次映射到 A 的输入。运行时序、缓存初态、后端及诊断开销并非完全相同。
- **构建来源。** fork 实跑 EXE SHA-256 为 `5a2cf8ed2444fa65709b2d9850bf17300c2a486e22543b28ef71996aa66503ea`；独立重链接 PE 只差 COFF / Debug 时间戳和 CodeView GUID，代码和数据未变。未运行上游脚本或发布二进制。
- **结论边界。** 同机同入口并非必然无法显示按 A 后的开场。fork 通常用独立宿主 RTV，不经过 VNME 的旧色准入；其一般地址式创建（vtable 槽偏移 `0x428`）降低为 `COMMON`，有优化清除值但不把它当写入，槽偏移 `0x470` 仍被忽略。尚未对齐两边的同一颜色操作，不能推断 fork 有该目标的有效底图，或把它的放行当作修复。两边均未取得可控场景、十分钟可玩、游戏内性能或发布验收证据。

## VNME 拒绝处与关键排除证据

首错绑定为 slot 0 / subresource 0，格式 29，3840×2160×1，单 mip，读目标旧色；没有已识别的同键前代或兼容字节来源（`13eee34`）。颜色目标为地址式创建，初始增强布局码 6，带优化清除值；目标范围内匹配 510 个同一 XMem section 的页（`df5dcfd`、`64dd795`）。这 510 页是按现有布局模型识别的候选范围，不是整个分配大小的实测。`94861f1` 与 `64dd795` 均通过开场 XMem 准入，后者未出现更早的上传快照冲突；两者仍在按 A 后遭遇同一颜色拒绝（记录 `8294e04`）。

| 已检验的假设 | 实际证据与不能推出的结论 |
| --- | --- |
| **已识别批内操作可以提供旧色** | `64dd795` 的未提交前缀 0–14 中，五个已识别原生写均非同目标；唯一匹配目标的增强屏障（第 14 项，无弃旧标志）不生产像素。`0x470` 的 ABI 与副作用未证。`b40a245` 的前缀无来宾字节复制、显式纹理上传或纹理复制；`8c7269a` 的前缀固定页计划中 10 张声明脏页也无目标命中。`8aa9317` 的 WARP 队列夹具确认同目标前置整面清除能供混合 draw 读取（真实 Fence 后核对像素），缺失、局部、后置清除不能通过；`5e59087` 进一步经来宾描述符录制确认换到异对象也不能通过。对照验证生产者门禁，不证明实机有生产者，也不独立证明来宾 ABI。 |
| **历史原生写或字节写回命中同一分配** | `3a63016` 保留的 2,248 个完成 Fence 中，记到的原生写候选均为默认私有堆，记录的分页 GPU 写回未命中目标。原生 Windows 夹具 `655b848` 证明两 VA 可共享同一受管 section 的真实字节，但当前映射不能把活跃的普通默认图形堆当成 section 源。此结论只排除当前实现下的直接映射，不排除间接复制、漏译或未观测路径。 |
| **DirectStorage 或零页已说明内容** | `20d0ad1` 记录的 9,894 次裸 VA 写入没有候选 VA 重叠，保留的 1,655 个 section 候选页也无命中；有 360 次采样不完整，不能排除所有写入。`9e65b0d` 一次有界只读观察中，CPU 此刻读到的 510 页全零；不证明按提交顺序该读者有权消费零底图，或 GPU、别名从未写过。 |
| **已知页数足以选用 `SW_64KB_R_X` 转换** | 公开 GFX10 addrlib 的合成对照 `1ebde91` 中，要求元数据与不使用元数据的两种模式可有相同的 510 页主平面及相同偏移；`cb3ff7b` 夹具还证明改变 pipe 配置会改变同一 texel 的偏移。不能从页数、格式或同源 XG/GPU 布局计算推出实机 tiling/XOR、压缩解释或最新字节版本。受限转换不等于实机可恢复。 |
| **混合读者自身可消除对旧色的依赖** | `7174c48` 记录实际 RGB 与 Alpha 均用 `ADD(SRC_ALPHA, INV_SRC_ALPHA)`。`425a069` 的 WARP 对照中，不透明输出且整面覆盖才使该例结果与底图无关；相同 Alpha 但弃掉半面时仍依赖底图。`8c7269a` 以 DXIL 字节匹配确证诊断对应实际绑定 PS，输出分类为 `Unknown`，未证明 Alpha、覆盖或翻译错误（`d8b709c`）。不因签名、视口或此结果放宽准入。 |
| **创建或 XG CPU 复制暗中写了目标** | `812ceb9` 的 Windows 合成 section 对照表明：地址式创建与 RTV 创建保留映射字节，不发布原生颜色版本；布局转换和优化清除值不能让相同读者通过。`8b216e0` 的 HLE vtable 夹具证明：同形状默认 R_X 的有效 XG copy-in 返回 `E_NOTIMPL` 且不写，显式 row-major 对照可写。这不证明实机调过或没调过 XG 或其他 CPU 写入入口；不能用未见告警替代调用证据。 |

## 待回答的问题：同一旧色读者在哪里首次分歧？

先按来宾创建描述、分配生命周期、实际 RTV/SRV 绑定、混合状态以及相对命令和提交顺序配对；不按 draw 序号、尺寸或虚拟地址配对。**能否找到 fork 在同一读者之前、对同一分配实际产生或保留有效旧色，而 VNME 没有等价处理的第一处操作？** 候选包括实体写入、对象重用、命令解释或后备交接，但必须能确认目标、覆盖范围与顺序。

若配对后找到差异，用单一改变的正反对照验证它是否影响该读者的可见内容，再决定修复或重构。若不能配对，或只证实参考实现没有拒绝，不能把它当成内容生产者，也不继续扩大同一批次的记录。走字节恢复路线须先有独立且能归属到同一分配的初始化、主平面和压缩/元数据契约，以及读者应见的权威字节版本；原生路线须有可归属、在读者之前且覆盖充分的生产者。证据不足时保留真实 Fence、内容门禁与无 Shadow 回退的要求，按[开发原则](development.md)止损换路。
